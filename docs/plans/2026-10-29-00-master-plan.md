# Claude Desk Prototype — Master Plan (architecture, contracts, schedule)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This master plan owns the repo scaffold, the shared contracts and the schedule; each subsystem has its own plan (index below) that consumes these contracts.

**Goal:** A hosted Claude Desk prototype where strangers and agents talk to a business's public Claude, every tool call and reply passes code checkpoints decided by a Rust/Cedar safety kernel, and the owner app shows approvals, rules and a provable safety ledger.

**Architecture:** Two processes in one ECS task. The **API service** (Python/FastAPI, port 8700) runs the agent loop, visitor/owner APIs and SSE; it holds only the Anthropic API key. The **kernel service** (Python/FastAPI on 127.0.0.1:8701, not exposed) holds every business credential (Stripe, MCP tokens, ledger signing key, approval HMAC key) and imports the Rust `desk_kernel` module (PyO3) for Cedar decisions, proofs and ledger hashing/signing. The React (Vite) web app is static on S3 + CloudFront and talks only to the API service.

**Tech Stack:** Python 3.13 (uv), FastAPI, Pydantic v2, SQLAlchemy 2 + Alembic, Postgres 16 (RDS), Procrastinate, sse-starlette, `anthropic` Python SDK, `mcp` Python SDK, `stripe` (test mode); Rust stable + PyO3 + maturin, `cedar-policy` 4.x crate, Cedar CLI with `symcc` (experimental) + cvc5, `ed25519-dalek`, `sha2`; React 18 + Vite + TypeScript, openapi-typescript client; AWS: ECS Express Mode (Fargate + ALB), RDS Postgres, S3 + CloudFront, Secrets Manager, CDK (Python).

**Spec:** `docs/specs/2026-10-28-claude-desk-design.md`. Designs: the Claude Desk design canvas linked from the spec.

## Review Focus

- A visitor claims to be the owner or another customer and asks for private documents → refused (baseline), logged, and the reply reveals nothing about the record.
- A visitor types a new email/phone and asks for the code to go there → code goes only to the contact on record; the typed contact is stored as a note, never as the record.
- Claude's draft reply contains a price/discount/date no tool issued (e.g. "80% off") → reply blocked/rewritten before reveal; violation logged.
- An owner approval arrives after the visitor left or after the run was cancelled → the held action resolves once (idempotent), never executes twice, and the ledger shows the outcome.
- A connected MCP server changes a tool definition after pinning → the tool is disabled until the owner reviews; calls to it are refused.

## Shared contracts (`backend/desk/contracts.py`) — every subsystem plan uses these names exactly

```python
Level = Literal["public", "verified", "agent"]
Outcome = Literal["allow", "hold", "refuse"]
Effect = Literal["read", "change", "move_money", "send_message", "private_data"]

class Principal(BaseModel):
    id: str                      # "visitor:<uuid>" | "person:<uuid>" | "agent:<key_id>" | "owner:<uuid>"
    level: Level
    person_id: str | None = None # set when verified
    agent_limit_cents: int | None = None

class ToolProfile(BaseModel):
    tool: str                    # "native.quote" | "native.book" | "native.release_document" | "native.payment_link" | "mcp.stripe.<name>" ...
    effects: list[Effect]
    reversible: bool
    amount_arg: str | None = None
    recipient_arg: str | None = None
    record_owner_arg: str | None = None
    time_arg: str | None = None
    definition_sha256: str | None = None   # MCP tools only (pinning)

class ToolCall(BaseModel):
    call_id: str
    tool: str
    args: dict

class Review(BaseModel):          # output of decisions.decide() for the auto reviewer
    within_charter: float         # probability 0..1
    manipulation: float
    recommendation: Literal["allow", "hold", "block"]

class Decision(BaseModel):
    decision_id: str
    outcome: Outcome
    policy_ids: list[str]         # Cedar policies that determined it
    review: Review | None = None  # present only if Cedar needed it
    reason_plain: str             # owner-facing one-liner

class Label(BaseModel):
    readers: list[str]            # principal ids allowed to see this data; ["*"] = public
    record_owner: str | None = None

class Fact(BaseModel):
    fact_id: str                  # e.g. "quote:Q-1042", "booking:B-77", "charter:hours"
    kind: Literal["quote", "booking", "payment_link", "document", "charter", "knowledge"]
    value: dict
    label: Label

class ExecResult(BaseModel):
    call_id: str
    ok: bool
    output: dict
    facts: list[Fact]

class ReplyDraft(BaseModel):
    session_id: str
    text: str
    cited_fact_ids: list[str]     # Claude lists what each price/date/promise relies on
    language: Literal["en", "es"]

class ReplyVerdict(BaseModel):
    ok: bool
    text: str                     # original if ok, else the safe rewrite
    violations: list[dict]        # {kind: "unbacked_commitment"|"unentitled_data"|"language", span: str, detail: str}

class PolicyActivation(BaseModel):
    desk_id: str
    cedar_text: str
    status: Literal["active", "rejected"]
    version: int | None
    counterexamples: list[dict]   # from the prover, plain-language + raw
```

**Kernel HTTP API (127.0.0.1:8701, JSON, only the API process may call it):**
- `POST /decide` `{desk_id, principal: Principal, call: ToolCall}` → `Decision`
- `POST /execute` `{decision_id, approval_token?: str}` → `ExecResult` (refuses unless decision outcome is `allow`, or `hold` + valid owner approval token)
- `POST /check_reply` `{draft: ReplyDraft, principal: Principal}` → `ReplyVerdict`
- `POST /policy/activate` `{desk_id, cedar_text}` → `PolicyActivation`
- `POST /tools/connect` `{desk_id, server: "stripe"}` → `list[ToolProfile]` (drafted, pinned)
- `POST /approvals/sign` `{decision_id, answer}` → `{approval_token}` (owner answers only; API service passes the owner's authenticated request through)
- `GET /ledger/{desk_id}?verify=true` → `{entries: [...], chain_ok: bool}`

**Rust module surface (`desk_kernel`, imported only by the kernel service):**
- `PolicyEngine(schema: str, baseline: str)`; `.decide(desk_policies: str, request_json: str) -> str` (JSON `{outcome, policy_ids, needs_review: bool}`); with `needs_review=True` returned when the result depends on `context.review` (partial evaluation).
- `prove(schema_path: str, policies_path: str, invariants_dir: str) -> str` (JSON `{ok, results: [{invariant, ok, counterexample?}]}`)
- `Ledger(signing_key_hex: str)`; `.append(prev_hash: str, payload_json: str) -> str` (JSON `{hash, signature}`); `verify_chain(entries_json: str, public_key_hex: str) -> bool`
