# Claude Desk Prototype — Plan 04: Web App

> **For agentic workers:** Execute with the repo's `executing-implementation-plans` skill (`.agents/skills/`): a fresh implementer and a task review per task, in the plan's worktree. The plan runs as two runs, each landing through one PR after the review panel, green CI and the project owner's sign-off on its screenshots and recordings (AGENTS.md "Design PRs"): run 1 is Tasks 1–7 (the thin slice, merged before Plan 06b's Friday deploy), run 2 is Tasks 8–17 on a fresh worktree from `main`. Steps use checkbox (`- [ ]`) syntax for tracking. Browser work follows `.agents/skills/using-browsers`.

**Goal:** The web app in `web/` (owner app, public page, mock checkout, agent pages, setup, first-visit arrival, labelled vision mocks) from Plan 03's components, against a mock API (MSW), then Plan 02's API.

**Architecture:** A React (Vite) single-page app in Plan 03's `web/` package. Routes: `/` (the first-visit intro dialog over a static preview of Today), `/app/:deskId/*` (owner), `/app/setup/*`, `/d/:slug` (public page), `/d/:slug/agents` (Agent Card page), `/pay/:token` (mock checkout), `/vision/*`. Requests go through one route table (`web/src/api/routes.ts`, Plan 02's exact paths) and one fetch wrapper that Task 16 moves onto Plan 02's generated client. Visitor chat streams Plan 02's SSE (`EventSource`, `Last-Event-ID`); owner screens poll. In dev and tests a stateful MSW mock serves the same routes, its payloads validated against `backend/desk/contracts.schema.json` (in dev, once in the Vite dev server's process, so every tab shares it: Task 3b). The browser holds no token and never names its own copy or session: the API sets HttpOnly cookies and takes identity from `GET /whoami` (master "Data model").

**Tech Stack:** Plan 03's `web/` toolchain (Node 24, `engines` `^24.15.0`; React 18.3.1, TypeScript 6.0.3, Vite 8.3.4, Vitest 5.0.4 with `@vitest/browser-playwright` 5.0.4 and Playwright 1.64.0, Storybook 10.6.2), plus, pinned exactly and published at least two weeks before this plan: `react-router` 7.18.4 ([library mode](https://reactrouter.com/start/library/installation); 8.x needs React 19), `@tanstack/react-query` 5.104.2, `msw` 3.0.3 ([`sse()`](https://mswjs.io/docs/sse/)), `ajv` 8.20.0, `qrcode` 1.5.4 with `@types/qrcode` 1.5.6, `vitest-browser-react` 2.3.0, `axe-core` 4.14.0, `@playwright/test` 1.64.0, `@axe-core/playwright` 4.13.0. ## Global Constraints

- Deadline Monday 2026-11-02, with a scope gate Friday 18:00 ("Schedule, lanes and gates"). Never cut: proofs at activation, data labels, reply checks, the attack gate.
- Models: `claude-opus-5-5` (conversations), `claude-sonnet-5-5` (auto reviewer), `claude-haiku-5-5` (soft-promise check, triage, owner translations), set up as "Model cost and latency budget" says, and the same three on every provider: local evals may send the API's and the simulated visitor's calls to Amazon Bedrock (`MODEL_PROVIDER=bedrock`, Plans 02a and 05b), while the hosted demo stays on the Claude API. Structured outputs use `output_config.format`, never forced `tool_choice`, which returns 400 on Opus 5.5 and Sonnet 5.5.
- The API holds only `ANTHROPIC_API_KEY`, the `desk_api` role and the built-in agent's demo key (and locally, with `MODEL_PROVIDER=bedrock`, a Bedrock-only credential that can call nothing but the three models, never the default AWS credential chain and never in production, Plan 02a), sends the kernel no principal, person, level or assurance, and can't write kernel tables ("Trust boundary").
- Every tool call except `send_reply` goes through `/decide` and executes only on a fresh `allow` or a single-use owner approval, both re-decided at execution ("Decision semantics"). Every visitor-visible message, card and status line passes the kernel and leaves through `deliver()`, except the kernel-served items listed under Delivery ("Reply check and visitor-visible text").
- Amounts come only from the kernel; prices, discounts, dates and policies appear only in clauses rendered from facts; documents and messages go only to entitled recipients ("Decision semantics", "Reply check and visitor-visible text", "Invariants").
- Rules: Claude drafts rule cards, `compiler.py` emits Cedar, proofs gate activation, the owner confirms. No hand-written or model-written owner policy is ever activated (the baseline is hand-written and reviewed in the repo). Review scores are integer basis points that can only narrow ("Decision semantics").
- Always-on baseline, each item enforced where named: AI disclosure on every visitor surface and A2A response (static notice, `A2AResponse.disclosure`, soft-promise check); private data only to the verified record owner, recipients only `owner` or `verified_contact`, no `pay_out` for agents, and an `Agent` `charge` requires `principal has mandate_remaining_cents && context has amount_cents && context.amount_cents <= principal.mandate_remaining_cents` (forbids in `cedar/baseline.cedar`, proved by `invariants/always/`); verification codes only to the contact on record (`/verify/start`); no `charge` or `pay_out` without an owner card or approval (step 5, `money_needs_card`); auto-allowed money ≤ the money cap `auto_money_cap_cents` of the Desk's active rules version (unset is 0, so every charge and payout asks) and never above `AUTO_MONEY_HARD_CAP_CENTS`, the $10,000 platform ceiling per action (baseline forbid, compiler cap, `invariants/auto/`; "Money cap"); every attempt logged (same-transaction ledger entries, "Data model").
- Also constraints, each in its section: demo-code verification with no real email, SMS or push; payments fully mocked, with no provider account, SDK or keys; per-visitor copies of the Rivera Plumbing seed, a shared Desk link granting visitor access only; the organization's $1,000 monthly limit shared by evals and the demo.
- Accessibility: WCAG 2.2 AA contrast for every token pair; status never by color alone; keyboard paths for chat, approvals and take-over; `aria-live` for replies and receipts; reduced motion respected; Plan 03 runs axe on every story.
- Product name "Claude Desk"; copy is sentence case, plain, no door/knock wordplay; footer "Concept prototype by Giovanni Alcantara, not an Anthropic product"; no Claude/Anthropic logos. Design system v2 tokens (warm dark: app #1C1B19, panel #222220, surface #2A2927, selected #3C392F; Source Serif 4 for Claude's voice and titles; Hanken Grotesk UI; clay #E08968 only in the mark and the first-visit intro dialog's illustration; checkpoint results as receipts attached under each message, at every width). Where the design canvas differs from this plan, this plan wins; canvas-only interactions (a counter-offer answer, a translated take-over message) stay static vision.
- Git: small conventional commits, written for readers of the public history, each ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

Specific to this plan:

- **Plan 03 components only.** Screens import UI from `web/src/ds/index.ts` and add layout with token custom properties only. Plan 03 owns every component and prop (Plan 03a's `PublicShell.footer` and `aboutLinks`, `Composer.maxLength`, `TakeOverBar.agent` included). **Consumes** lines omit Plan 03's components; error and status copy is Plan 03's (`errorCopy`, `evErrorCopy`, `UNREACHABLE_COPY`, `CHAT_ENDED_COPY` with `NEW_CHAT_LABEL`, `RATE_LIMITED_COPY`).
- **Visitor surfaces** (`/d/:slug`, `/d/:slug/agents`, `/pay/:token`) show outside `deliver()` only the master's Delivery allowlist ("Reply check and visitor-visible text"), `PublicDesk`, `PaymentLinkView` and Plan 02's code-built `AgentCardOut` included. Model text reaches a visitor only as a delivered `EvMessage` or a Desk reply's blocks: the built-in agent's own words are never rendered. Receipts are `visitor_plain` through Plan 03's `receiptFromEvent`. No money or date formatting except the checkout amount from `amount_cents`. A message's cards follow `EvMessage.language`; page chrome follows the browser.
- **Identity and session state.** The browser sends no copy, session or generation as authority: IDs in owner paths only name a record the API checks against `/whoami` (outside the copy → 404, the not-found screen). On visitor surfaces a 401 (a closed stream included) or `EvError{code: "session"}` shows `CHAT_ENDED_COPY` with `NEW_CHAT_LABEL`; a silently ended turn ("Fail-closed behavior") shows nothing, and its `turn_end` clears "Claude is writing". Other `EvError` codes show `evErrorCopy`, never the code.
- **No secrets in the browser.** No `document.cookie`, no `X-Owner-Session`, `X-Session-Token`, `Authorization` or `Cookie` header; `credentials: "same-origin"`; bodies are parsed only into typed fields (`code`: the body's `code` when `error` is `"kernel"`, else `error`; `retry_after`; a 409's `decision`, `state` or `draft`; a 202's `retry`), never rendered.
- **Uncertain outcomes.** A write whose answer is lost (fetch failure, timeout or 5xx) may have been applied, so it is never reported as not done: the screen reads the current state first (Tasks 3, 5). Inputs stop at Plan 02's limits (messages and answers 2000 characters, setup description 1500) with a counter from 90%.
- **Owner receipts.** On owner screens the status receipt that reports a decision's decide outcome is the first status event in the transcript for its `decision_id`: an `EvHeld` for a hold, an `EvReceipt` for a refusal, and for an allowed action its one `EvReceipt`, which the API sends after `/execute` with the decision's final state (the API core plan's Task 4, plan 02a: one `Status` per decision), so an auto-allowed action's receipt usually reads `executed`, never `allowed`. When that first receipt's `state` is `held`, `refused`, `executed` or `allowed`, it shows the decision's owner line, `Decision.reason_plain` ("why did Claude do this on its own?"), read by its `decision_id` through `decision` (Task 8's `useOwnerReceipt`); until that read answers, or if it fails, it shows the event's `visitor_plain`. A first receipt that reads `failed`, `unknown` or `refused_at_execution` keeps its `visitor_plain`, since the reason it was allowed would contradict what happened, and so does every later status event for the same decision (`approved`, `denied`, `executed` and the rest after a hold), because `reason_plain` is written once, at decide time, and the words must follow the state as the dot does. Reply receipts and every visitor surface, the owner's own chat as a customer included, keep `visitor_plain`. No contract changes, and visitor SSE events stay as they are.
- **Owner UI is English and plain.** Rendered owner copy avoids: policy, Cedar, MCP, SymCC, kernel, schema, JSON, API, token, proof, proven, hash (the full trace and quoted untrusted text are exempt). Owner times and amounts are formatted in `web/src/lib/format.ts`, in the business's time zone.
- **Polling.** React Query intervals (`POLL_MS`, ms): `needsYou` 3000, `today` 5000, `conversation` 2000, `list` 5000, `inbox` 5000, `rules` 5000 (Integrations), `safety` 10000, paused while hidden; tests scale them with `setPollScale`.
- **Mocks never ship.** MSW lives only in modes `mock` (in the dev server's process, Task 3b) and `test` (the in-page worker, public dir `web/mock-public/`); the build holds no MSW code (Task 7).
- **States.** Every screen has loading, empty and error states whose copy names a next step. Once an owner request has succeeded in the tab, an owner-route 401 returns to `/`, where the intro dialog's intro opens with "Your demo session ended. Enter the passcode to start a fresh copy."
- **Storage.** localStorage holds only the hidden "Things to try" flag and the last Desk, through `readLocal`/`writeLocal`, which never throw.
- **Viewports.** Desktop first (1440×900), unbroken at 390×844 (no horizontal scroll or clipped text).

## What this plan serves

- The two "oh, this is real" moments in a browser: a stranger chats with Rivera Plumbing's public Claude and sees a checked reply with its receipt; the owner answers a held request in one click and the chat continues.
- The owner's side of "can't be talked around": stopped attempts with plain reasons and a signed, chain-checked record, take-over, whispers and a tool-change review.
- A first visit with no setup: an intro dialog over a still preview of Rivera's Today that lists four things to try and takes the passcode, then Rivera's Today as Maria, with her public page a click away in a new tab, this week's real figures and its own things to try.
- The 12-month direction: someone else's agent visiting under a signed spending limit, and labelled vision screens.
