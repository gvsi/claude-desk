# Claude Desk Prototype — Plan 06a: CI checks

> **For agentic workers:** Execute with the repo's `executing-implementation-plans` skill (`.agents/skills/`): a fresh implementer and a task review per task, in this plan's worktree, landing through one PR after the two-reviewer panel. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every push to `main` and to a pull request runs the backend and kernel tests, the proofs on the shipped rules, the model-free attack suite and a secret scan; a pull request to `main` that changes gated inputs also needs Plan 05b's tier 2 results check. A suite whose code hasn't landed skips and says so; once its code exists, a missing suite fails. Lands Thursday morning, before any other plan's pull request.

**Architecture:** One GitHub Actions workflow (`.github/workflows/ci.yml`) with nine named jobs, a composite setup action, and a stdlib gate (`tools/desk_tools/gate.py`) that decides run, skip or fail for each suite another plan owns. The workflow calls only the make targets the owning plans publish and reimplements none of them.

## Global Constraints

The master plan's "Global Constraints" apply as written. Specific to this plan:

- **No secrets, least privilege.** CI holds no secret and no Anthropic key. Workflow `permissions: {contents: read}`, never widened; no `pull_request_target`; every checkout `persist-credentials: false`; actions pinned by SHA; downloaded tools checked with `sha256sum -c`.
- **Gates fail closed.** A check skips only while its code doesn't exist, and says so in the job log and summary. The gate decides by paths alone and never probes make: once the paths that mark a suite's code exist, it runs the suite's make target, so a missing target or a Makefile error is a failure, never a skip; once a `--required-if` path exists, a missing suite fails.
- **Consume, never reimplement.** Tier 1 is `make evals-tier1` (Plan 05a) and the tier 2 check is `make evals-results-check BASE=origin/main` (Plan 05b); proofs are `make check-presets` (Plan 01a, which re-proves every shipped report). What they check belongs to their owners.
- **Evals gate.** No kernel, prompt or policy change here; this plan runs the gate and changes nothing gated.
- **Owner calls.** Branch protection and any paid runner minutes are the owner's.

**Fail closed here:** beyond the gate table below, two Alembic heads fail `backend tests` before migrating; a shipped proof report missing, stale or failing fails `proofs`; gated inputs changed with no passing tier 2 results file fail `tier 2 results`; a secret in the history fails `secret scan`, redacted.

## What this plan serves

- The product's safety claims are re-checked on every push: tests, proofs on the shipped rules, the model-free attack suite and a secret scan; a gated change can't merge without its tier 2 result.
- It lands first, so every other plan's pull request is checked from its first push.

**Produced:** the nine check names `backend tests`, `kernel tests`, `proofs`, `tier 1 evals`, `tier 2 results`, `web tests`, `infra synth`, `secret scan`, `repo checks` (listed in `docs/ci.md`); the gate contract; the `setup-desk` composite action; the uv project `tools/` with `tools/cvc5.sha256`; make targets `web-test` (`cd web && npm ci && npx playwright install --with-deps chromium && npm run typecheck && npm test`) and `web-e2e` (`cd web && npm run build && npm run check:build && npm run e2e:mock`, Plan 04's request).

**Gate contract** (`tools/desk_tools/gate.py`): `uv run --project tools python -m desk_tools.gate --name <name> --run-if <path> [--run-if <path>]... [--required-if <path>]... -- <command…>`. Paths are relative to the working directory (the repo root in CI). The `--run-if` paths mark the suite's code as present; the gate never reads the Makefile, so the command itself decides whether the target exists.

| State | Result |
|---|---|
| every `--run-if` path exists | runs the command; exits with its code (a missing make target or a Makefile error fails) |
| a `--run-if` path is missing and a `--required-if` path exists | exits 1 without running the command: "`<name>` is required by `<path>` but `<run-if>` is missing" (the first existing `--required-if` path, the first missing `--run-if` path) |
| a `--run-if` path is missing and no `--required-if` path exists | exits 0 without running the command; prints "`<name>`: skipped, `<run-if>` is not in the repo yet" and appends it to `$GITHUB_STEP_SUMMARY` when that is set |
| usage error (no `--`, no command, no `--name` or `--run-if`, an empty path, or a `make:<target>` value, which the gate doesn't probe) | exits 2 without running anything |
