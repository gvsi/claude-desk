# Claude Desk Prototype — Plan 06b: Deploy and docs

> **For agentic workers:** Execute with the repo's `executing-implementation-plans` skill (`.agents/skills/`): a fresh implementer and a task review per task, in the plan's worktree. The plan runs as two runs, each landing through one PR after the review panel and green CI: run 1 is Tasks 1–7 (the deploy code, merged Friday before Task 8 deploys that merge), run 2 is Task 9 (README, threat model, decisions; Saturday) on a fresh worktree from `main`. Steps use checkbox (`- [ ]`) syntax for tracking. Browser work follows `.agents/skills/using-browsers`.

**Goal:** The prototype runs on AWS as one same-origin URL: the kernel a local-only sidecar holding every credential, the origin reachable only through CloudFront, every deploy pinned to a merged commit with a passing tier 2 result. The repo explains itself: a README that runs, a threat model claiming only what is enforced, the architecture decisions, and a path to an MVP from measured numbers.

**Architecture:** The app image (`infra/app.Dockerfile`, outside the gated `kernel/` tree) layers the backend on master Task 1's kernel image and runs as two containers in one Fargate arm64 task: the kernel on 127.0.0.1:8701 and the API (`Main`, 8700) behind a load balancer. CDK (Python) stacks in us-west-2: `DeskData` (VPC without NAT, private RDS, generated secrets, security groups, the admin task) and `DeskApp` (the task, the ECS Express Mode service with its load balancer locked to CloudFront, one distribution for S3 and `/api/*`); the fallback serves the same task from an internal ALB through a CloudFront VPC origin. The owner runs every AWS-mutating command.

AWS: ECS Express Mode (`CfnExpressGatewayService`), Fargate arm64, ALB, RDS PostgreSQL 16.13, S3, CloudFront (Functions, VPC origins), Secrets Manager, Lambda, CloudWatch Logs. The master plan's "Global Constraints" apply as written. Specific to this plan:

  - Status (2026-10-30): the owner decided that redeploys run with one command and no prompts, which supersedes the `read -rs` parts of the two constraints above and of Task 8 for every deploy, and their owner's-own-terminal part for redeploys only: Task 8's first deploy (Steps 2 to 4) still runs in the owner's terminal, as docs/deploy.md's "First deploy" section shows. - **Only CloudFront reaches the origin.** Browsers reach the API only at `/api/*` on the distribution, so cookies stay first-party and `X-Forwarded-For` holds the real viewer. No distribution-wide error responses (they mask API errors); SPA routes are rewritten on the S3 behavior only.
- **Region and architecture:** us-west-2, arm64 for all AWS compute, one image for both containers.
- **Docs claim only what is measured or enforced.** Numbers come from Plan 05b's report or a cited measurement, else read `estimate:` with their formula; owner links stay `[owner: …]` until filled; the final check fails on any placeholder in the shipped docs.
- **Evals gate.** No kernel, prompt or policy change here: the app image lives in `infra/`, outside Plan 05b's `GATED_PATHS`. **Fail closed here:**

| Failure | Behavior |
|---|---|
| A database URL part or secret is missing | The entrypoint exits before the service starts, naming the variable, never its value |
| The kernel container is unhealthy, or refuses to start in production (a test hook set, `MOCKPAY_KEY` under 32 characters) | `Main` never starts (`dependsOn` `HEALTHY`); the task is replaced |
| Preflight fails (dirty tree, commit not on `main`, no passing tier 2 results file, owner secrets unset, web build check) | `deploy.sh` stops before any AWS call |
| The admin task fails | `deploy.sh` stops before `DeskApp`; nothing new serves traffic |
| The origin lock can't be applied | the custom resource fails and `DeskApp` rolls back |
| A smoke check fails, the origin answers directly included | the deploy is reported failed; the thin slice isn't announced |
| Express can't run the task, or re-opens its load balancer | Task 8 switches to the fallback, recorded as a ruling |
| A seed or preset report missing or stale in the image | `make image-check` fails (Task 8's preflight runs it); in production, copy creation answers 503 `seed_unproved` and `Health.unproved_seeds` lists the preset after the first miss |

- No container sets a test hook (`DESK_DECISIONS`, `DESK_PROVE`, `ANTHROPIC_BASE_URL`).
- `*_DATABASE_URL` is a SQLAlchemy URL, `postgresql+psycopg://<user>:<url-encoded password>@<host>:<port>/<db>?sslmode=require`, the same form as `.env.example`. A consumer that bypasses SQLAlchemy (Procrastinate's `PsycopgConnector`, plain psycopg) passes `make_url(url).set(drivername="postgresql").render_as_string(hide_password=False)`. Generated database passwords are alphanumeric.
- `PUBLIC_ORIGIN`: the API builds every absolute link from it in every environment (the Agent Card `endpoint`, `go_live`'s `public_url`, share links); production value `https://` plus the custom domain, else the distribution's `PublicUrl` (`DeskConfig.public_origin`, set by `deploy.sh`). No request header sets it.
- `TRUSTED_PROXY_HOPS`: the API's client address for per-IP limits is the `TRUSTED_PROXY_HOPS`-th address from the right of `X-Forwarded-For`: 2 in production, since CloudFront appends the viewer's address and the load balancer appends CloudFront's; fewer entries or an invalid address → one shared bucket; 0 (the local default) uses the socket peer. Only CloudFront reaches the origin (Tasks 4 and 6), and it always appends the real viewer, so the entry can't be forged.
- The API reads neither `X-Desk-Public-Host` nor `CloudFront-Viewer-Address`; the edge sets no custom header.

**Edge contract** (Plans 02 and 04): `/api/*` reaches the API with every viewer header, cookie and query string except `Host`, plus the `X-Forwarded-For` entry CloudFront appends; uncached; 60 s origin read timeout. Everything else is the S3 web build; extensionless paths serve `/index.html`.
