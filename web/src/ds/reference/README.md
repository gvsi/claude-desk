# Reference boards

The design system is checked against the design canvas boards the project owner signed off, listed once each in `REFERENCE_BOARDS` (`boards.ts`). Run 2's boards (`N-Run2-*`, `N-R2-*`), drawn on 2026-10-29, are listed too while they are in review: each one's story says "built against the board in review; sign-off pending" until the owner signs it. Every story names its board in `parameters.canvas`, or says `'none'` with a `canvasNote` naming the nearest board, and the project's story hooks fail a story that doesn't.

## How a board is checked

- **A board story.** Each board is rebuilt by one `Boards/*` story in `web/src/ds/boards/`, from the components and the fixtures. What no component draws, because the web app (plan 04) owns that page's layout, is composed beside the stories in `boards/parts.tsx` and `boards/boards.css`, on the tokens. Each story's `canvasNote` lists what differs from its board.
- **Its play.** It asserts the board spec below with `expectComputed`, checks that receipts sit 8 px under their message on its side, and walks the page with Tab (`focus_order_is_logical`). The spec rows are `boards/spec.ts`; a row that differs between boards is one row per board.
- **By eye, and by the pixel.** Each story is compared with its board's render at the window the board is drawn at, where the values the spec asserts are also read off the render (colors, edges and spacing, pixel for pixel), then checked at 1440×900 and 390×844 for sideways scroll and clipped text, with a keyboard walk that shows the 2 px blue ring at every stop. A value the render shows is the one the story matches; only content, and the decisions signed after a board, may differ from it.
- **Each board at its own window.** Most boards are drawn at 1280×820, the Storybook "Canvas" viewport; the recorded-history boards and run 2's laptop boards are drawn at a 14-inch laptop's 1512×982, the "14-inch laptop" viewport; N-Docs-Sidebar is the sidebar alone, 264×982, the "Sidebar alone" viewport; run 2's phone boards are 390×844, the "Phone" viewport; and a run 2 page longer than the window is drawn at the laptop's width and its own height (1512×1100, 1512×1150 or 1512×1500), a viewport of its own. `BOARD_VIEWPORTS` and `boardViewport` in `boards.ts` say which, the preview builds its viewports from them, and each board story sets its board's viewport in `globals`, so its play runs at that window in Vitest too.
- **The renders stay out of the repository.** They are rendered from the canvas to a folder on the checking machine. `boards.test.ts` checks there is one per board, at its board's size (1280×820, 1512×982 for the laptop boards, 264×982 for the sidebar alone, 390×844 for a phone, or a longer page's own height), when `DS_REFERENCE_DIR` names that folder, and skips otherwise. It also checks that every board story runs at its board's window:

```sh
cd web
DS_REFERENCE_DIR=/path/to/reference npx vitest run --project unit src/ds/reference
npx vitest run --project storybook src/ds/boards
```
